# ADR 012: Loopback one-command review launcher

- **Status:** Accepted for local review
- **Context:** The dashboard's old default API address pointed at port 8000, where an unrelated Uvicorn process returned 404 for the demo API route. Manual two-terminal configuration also allowed the API port and dashboard API URL to drift.
- **Decision:** Keep `scripts/run_project.sh` as the foreground/setup/check/smoke wrapper around the typed Python launcher, and provide `scripts/run_all.sh` as the normal managed entry point. Default API/dashboard ports are 18000/5173; only `127.0.0.1` is accepted. The Python launcher checks files, interpreter, imports, and ports; supplies the actual API base and CORS origin; waits for health and dashboard readiness with finite deadlines; and terminates only its own process groups with bounded escalation and verification. The master shell launcher checks identity before signalling that manager and stores its PID metadata/log in ignored `var/run-all/`.
- **Alternatives considered:** Continue requiring users to edit `config.js` (rejected as fragile); kill listeners on selected ports (rejected as unsafe); replace the current standard-library WSGI/static stack (unnecessary to fix the integration mismatch); bind to all interfaces (rejected for the local review demo).
- **Consequences:** One documented command starts, inspects, logs, restarts, and stops both services without changing port configuration in source. A port conflict fails before service creation and requires a different port. Python handles service process ownership and bounded cleanup; the shell wrapper resolves the repository root, uses the existing `.venv`, and does not recreate it.
