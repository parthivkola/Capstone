# ADR 014: Keep live detection unavailable until rule-counter evidence passes

- **Status:** Accepted for attack classification and mitigation; provisional non-classifying anomaly scoring was later added in ADR 016.
- **Context:** The application has a loadable offline model for the 77-feature CICFlowMeter schema and separate code for four OpenFlow rule-counter features. Existing Stage 7 telemetry files include legacy collection records and timestamp-order failures. The current evidence audit reports no source-verified feature pairs. The host's system OVS database cannot be inspected by the current user, so the active lab bridge scope is unknown.
- **Decision:** Do not train, approve, or expose operational live inference or mitigation from the available evidence. Preserve the offline model path and show the live model as unavailable. Require a reviewed rule-counter collection plan, corrected source telemetry with verified epoch/request/reply/snapshot linkage, nonzero audited feature pairs, run-grouped training/validation/test data, and explicit lab approval before enabling the live detector.
- **Alternatives considered:** Reuse the offline model (rejected: incompatible schema and feature semantics); label old telemetry by scenario filenames (rejected: invalid source lineage, event timing, and packet-evidence contamination); train on synthetic fixtures (rejected: not observations); enable a heuristic or mitigation-only path (rejected: no validated predictive evidence and unsafe claim).
- **Consequences:** Live detection and defense remain blocked while the local offline workflow remains demonstrable. The next concrete work is source-side Ryu timestamp/lineage correction, followed by a separately authorized isolated rule-counter validation and review of its output before collecting labels.
